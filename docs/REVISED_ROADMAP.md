# AI Atölye — Revised Roadmap

This replaces the milestone list of the original master specification. Status is kept current in [`DEVELOPMENT_STATUS.md`](../DEVELOPMENT_STATUS.md); the reasoning is in [`ARCHITECTURE_AUDIT.md`](ARCHITECTURE_AUDIT.md).

**Strategy:** AI Atölye orchestrates the learning journey; it is not a compute provider. There are three execution environments:

| Lab | Runs on | Cost to us | Used for |
|---|---|---|---|
| **Visual Lab** | Student's browser (TypeScript) | ≈0 | Concepts, experiments, small real models |
| **Python Lab** | Student's browser (Pyodide in a Web Worker) | ≈0 (CDN) | Real Python, lightweight ML, graded challenges |
| **Colab Lab** | Student's own Google Colab session | 0 | Larger datasets, longer training, scikit-learn/NumPy/pandas ecosystem |

No GPU servers, no per-student kernels, no Kubernetes, no Python execution in API workers.

**Primary acceptance workflow:** lesson → visual experiment → generated Python → edit and run Python → open a notebook in Colab → train → export a report → import it → evaluate → complete the project.

## Expected bottlenecks (to be measured, not assumed)

- First Python run downloads ~10 MB of Pyodide per student (cached by the browser afterwards).
- School networks may block jsDelivr or Colab; self-hosting Pyodide removes the first dependency.
- API load is limited to debounced snapshot saves and small JSON reports; a single instance should serve a pilot, but no capacity claim is made until load testing is done.
